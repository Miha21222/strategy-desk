### Почему опрос идёт через CLI, а не через модель

MCP-тулы вызывает модель, а не приложение. Если «приложение следит за сессией» значит «раз в пятнадцать секунд запускаем ход модели», то план пользователя сгорает на том, чтобы узнать, что ничего не произошло. У tvmcp есть CLI, где каждый зарегистрированный тул — подкоманда, печатающая JSON в stdout:

```
uv --directory <tvmcp> run tv <tool_name> '<json args>'
```

Приложение опрашивает через него. Замерено на этой машине: **≈2.5 с на вызов**, и это целиком запуск Python + импорт fastmcp, одинаково для любого тула. Отсюда три правила, которые зашиты в код:

- опрос никогда не идёт чаще `next_poll_after_s` (пол 5 с, потолок 15 мин) и никогда не идёт параллельно самому себе — цикл цепочечный, следующий тик ставится только после того, как предыдущий вызов вернулся;
- таймаут с большим запасом (30 с, 120 с для сканов и стартов), таймаут — предупреждение, а не падение;
- предсессионный блок — три параллельных запуска, а не три последовательных: каждый всё равно платит те же 2.5 с.

### Что считает приложение, а что стоит хода модели

| Детерминированно, 0 токенов | Ход модели |
|---|---|
| `tv_scan_levels` — уровни до открытия, ADR, opening range | Событие, чей тип есть в `askModelOn` воркфлоу (для «Дня IB»: `RANGE_CLOSED`, `BREAK_CONFIRMED`, `SWEEP`, `CLOCK`) — **один ход на опрос**, по самому свежему событию, с полным списком в промпте |
| `tv_calendar_check` — события дня, праздники, ролловер | Кнопка «Спросить вердикт» |
| `tv_risk_guard` — вердикт по вашим правилам | Кнопка «Разобрать день» (после реплея) |
| `tv_journal_load` — сводка журнала | Быстрые действия воркфлоу |
| `tv_sentinel_start/poll/status/stop` — фазы, диапазон, пробои, снятия, отметки времени | — |
| Лента событий, фаза прогона, переподключение после перезапуска | — |

Реплей прошедшего дня не отправляет ходов модели вообще: владелец сам жмёт «Разобрать день», когда хочет разбор.

### Мастер настройки и диагностика (готово)

Приложение раньше молча предполагало рабочую машину: `uv` в PATH, папка tvmcp по
умолчанию, вход в Claude в `~/.claude`, TradingView на настроенном порту CDP. Когда
чего-то не было, пользователь видел жёлтую лампочку и чат, который падал позже, —
и никакого пути от «не работает» к «работает».

- `src/shared/preflight.ts` — контракт и чистая функция «факты → список проверок»;
  `src/main/preflight.ts` — только зонды (shell, HTTP на порт CDP, файлы). Девять
  проверок в одном порядке: `uv`, папка tvmcp (в ней должен быть `pyproject.toml` с
  проектом `tvmcp`), запуск tvmcp (первая строка stderr — там и видно недостающую
  зависимость или не тот Python), вход в Claude, TradingView Desktop, владелец порта
  CDP, воркфлоу, которые не разобрались, и два необязательных файла дня.
- **Приложение само не делает ничего сетевого и ничего разрушительного.** `git clone`,
  установка `uv`, `uv sync`, вход в Claude и «закрыть TradingView» отдаются текстом с
  одной фразой о том, что произойдёт; кнопку нажимает человек. Само приложение умеет
  ровно три вещи: запустить TradingView, переключить порт в настройках и открыть
  системный диалог выбора файла.
- Ничего не кэшируется: «Проверить заново» означает настоящий перезамер (кэш `tvmcp
  --check` сбрасывается первым).
- `cdpProbe()` вместо булевой проверки порта: ответ на `/json/version` доказывает лишь
  то, что порт занят каким-то Chromium-приложением, поэтому зонд несёт строку `Browser`
  и список вкладок — и проверка называет владельца порта по имени. На машине владельца
  9222 занят FX Replay в браузерной панели, 9223 свободен.
- Мастер: Claude → uv и tvmcp → TradingView и порт → файлы. Открывается сам, пока не
  выставлен `setupCompletedAt`, и из настроек («Мастер настройки») в любой момент. Шаг
  можно пропустить; пропуск помнится в `settings.setupSkipped`, и ослабленная функция
  сама говорит почему (панель дня — что риск считается по примеру из поставки, сайдбар —
  почему лампочки красные) вместо загадочной ошибки через час. Ставший зелёным шаг
  перестаёт считаться пропущенным.
- Тот же список лежит в Настройках, раздел «Диагностика», со своей кнопкой перепроверки.
- `data/copilot-notes.md` — раздел «Live field notes» системного промпта: грабли, за
  которые уже заплачено (M7/M8/M9 tvmcp). Настройка `fieldNotesPath` позволяет указать
  свой файл; указанного файла нет — раздела просто не будет, это не ошибка. Заморозка
  промпта на чат не тронута: правка заметок видна новым чатам, у старых префикс кэша
  остаётся байт в байт прежним.
- `DESK_SMOKE=preflight npm run dev` печатает настоящий список проверок этой машины.

Реальный прогон на машине владельца (2026-09-20, TradingView была закрыта):
`uv 0.8.17` ok · папка tvmcp ok · запуск tvmcp ok (64 тула) · вход по подписке ok ·

### Упаковка (готово)

Установщик Windows: `npm run dist` → `release/Strategy-Desk-0.1.0-x64.exe`,
**166 МБ**. Из них ~226 МБ до сжатия — родной бинарник `claude.exe` из платформенного
пакета Agent SDK (`@anthropic-ai/claude-agent-sdk-win32-x64`); всё остальное
(Electron ~180 МБ, свой код 7 МБ в `app.asar`) занимает заметно меньше. Бинарник
лежит вне архива (`asarUnpack`), потому что SDK ищет его через `require.resolve()`
от своего собственного файла и потом запускает как процесс.

**Главный дефект, который чинила эта работа.** В `electron-builder.yml` список
`files` содержал `out/**`, `prompt/**` и `package.json` — и **не** содержал
`workflows/**` и `data/**`. В разработке это ничего не стоит: обе папки лежат в
рабочей директории, и приложение их находит. Установленная сборка стартовала бы
без единого воркфлоу (пустая вкладка «День») и без книги правил проп-фирм (пустые
карточки отчётов). Теперь обе папки в `files`, а поиск любого файла поставки идёт
одним правилом (`src/main/resource-paths.ts`):

```
dev cwd  →  app.getAppPath()  (= app.asar в собранном виде)  →  process.resourcesPath
```

причём кандидат `cwd` **выбрасывается**, когда `app.isPackaged`: у установленного
приложения рабочая директория — там, куда показывает ярлык (обычно `C:\WINDOWS`),
и читать оттуда файлы поставки нельзя. Правило отдельным модулем без Electron,
поэтому проверяется юнит-тестами.

Что ещё в сборке:

- **Иконка своя** — `build/icon.png|ico|icns`, рисует `scripts/make-icons.mjs`
  (`npm run icons`) без единой графической библиотеки: диапазон сессии двумя
  серыми рельсами и одна синяя свеча, закрывшаяся над ним. Ничего похожего на
  знаки TradingView или Anthropic.
- **Имя файла без пробелов**: `artifactName: Strategy-Desk-${version}-${arch}.${ext}`.
- **NSIS**: установка для пользователя (никакого UAC), выбор папки, ярлык на
  рабочем столе, `%APPDATA%\strategy-desk` при удалении не трогается,
  `differentialPackage: false` (сервера обновлений нет — blockmap был бы мёртвым грузом).
- **Автообновление выключено.** `publish: null`; в yml лежит закомментированный
  блок ровно с тем, что надо вписать для релизов на GitHub. Подписи кода тоже нет,
  поэтому SmartScreen будет ругаться на первый запуск — это ожидаемо.
- **tvmcp не пакуется**: приложение зовёт его `uv --directory <path> run …`, путь —
  настройка. Сборка нигде не предполагает, что клон существует.
- **`npm run dist:check`** запускает собранный бинарник с `DESK_SMOKE=pack` из
  `C:\WINDOWS`, а с флагом `--rename-project` сначала уносит `workflows/` и `data/`
  в сторону (и возвращает обратно даже при падении). Проверка печатает якоря,
  воркфлоу, книгу правил, размеры промпта — и **запускает** `claude --version`,
  потому что путь, который выдаёт SDK, ведёт внутрь `app.asar` и работает только
  благодаря подмене на `app.asar.unpacked`: найти файл мало, надо его запустить.
