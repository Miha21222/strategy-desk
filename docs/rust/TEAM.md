# Команда Strategy Desk на Rust

Как работает «отдел» агентов над ТЗ (`docs/rust/TZ.md`). Этот файл читает каждый агент перед началом работы.

## Роли и участки

| Роль | Владеет (пишет только сюда) | Этапы ТЗ |
| --- | --- | --- |
| Тимлид (главная сессия) | `rust/Cargo.toml`, `docs/rust/*`, `.github/workflows/rust.yml`, слияния | все: контракты, ревью, merge |
| desk-core | `rust/crates/desk-core/src/**` | 2 (чтение vault), чистая часть 4, 6, 21 |
| desk-app | `rust/crates/desk-app/**` | 3 (watcher), 4 (запись), 5 (драйвер Claude), 6 (лампочки, мастер, планировщик) |
| desk-ui | `rust/crates/desk-ui/**` | 1 (окно, тема), 3 (экран), 5 (чат), 6 (мастер) |
| QA · функционал | `rust/crates/*/tests/**`, `rust/fixtures/**`, `docs/rust/TEST_PLAN.md` | все: юнит-покрытие сверх авторского, golden, e2e, снимки UI |
| QA · перформанс | `rust/crates/desk-bench/**`, `scripts/rust/**`, `docs/rust/PERF.md` | все: бенчи, стресс, отчёт по метрикам |
| Релиз и CI | `rust/crates/desk-ui/build.rs`, `rust/dist/**`, `.github/workflows/rust-release.yml` | 7–8 (подключается на этапе 7) |

Ревью вторым мнением — Codex у владельца на его ПК, по PR в ветку `rust`.

## Правила

1. **Своя полоса.** Агент меняет только свои пути. Нужна правка чужого — пишет в отчёте, что и зачем; правит владелец участка или тимлид.
2. **Контракт раньше кода.** Типы между крейтами описаны в `docs/rust/CONTRACTS.md`. Меняет их только тимлид.
3. **Тесты пишет не только автор.** Автор кода пишет юнит-тесты своих функций. QA пишет независимые тесты по ТЗ и по поведению старого TS, не подглядывая в реализацию для подгонки.
4. **Эталон — старое приложение.** Пока Electron жив, правильный ответ для чтения vault — то, что даёт нынешний `loadDay()` (`scripts/preview/dump.ts` на vault из `scripts/make-demo-vault.py`). Расхождение с эталоном = баг Rust, если ТЗ прямо не меняет поведение.
5. **Ни одного секрета, ни одного файла реального vault в git.** Только demo-vault и синтетика. Реальный vault владельца в облако не копируется без его просьбы.
6. **Окно 16:25–18:30 по Киеву.** Ничего не запускать на ПК владельца (сборки, бенчи, TradingView). В облаке работать можно.
7. **Код по-английски, строки UI по-русски** (как в остальном репозитории). Комментарии объясняют «почему».

## Готово — это

- `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` зелёные в `rust/`.
- Новое поведение покрыто тестами автора; QA подтвердил своими тестами или golden.
- Нет `unwrap()`/`expect()` вне тестов и `main` без комментария, почему паники не будет.
- Отчёт агента: что сделано, что не сделано, какие решения принял сам, что сломается, если он неправ.

## Метрики (цели для QA · перформанс)

Каждая сборка меряется против базы «до» — нынешнего Electron 0.2.3 тем же стендом.

| Метрика | Как меряем | Цель |
| --- | --- | --- |
| Холодный старт до первого кадра | `bench.ps1`: запуск → первый кадр (лог `first_frame_ms`), медиана из 10 после перезагрузки кэша | ≤ 300 мс |
| Тёплый старт | то же, повторный запуск | ≤ 150 мс |
| RAM в покое | Working Set / Private Bytes через 60 с покоя | ≤ 80 МБ |
| CPU в покое | среднее за 60 с | ≤ 1 % |
| Кадр p50 / p95 / p99 | счётчик кадров при стриме Claude (10 тыс. событий) | ≤ 8 / 16 / 33 мс |
| Загрузка дня | `criterion`, ~22 файла дня | ≤ 30 мс |
| Перерисовка после изменения файла `state/` | от записи файла до нового снимка | ≤ 350 мс (дебаунс 300) |
| Переключение экрана / дня | от команды до кадра | ≤ 100 мс |
| Размер exe / установщика | файлы релиза | ≤ 15 / 20 МБ |
| 24 ч работы | рост Private Bytes | ≤ 5 % |

Стресс: vault ×10 (2 года синтетики), 10 тыс. событий stream-json подряд, чтение файла во время записи, битый и обрезанный JSON, обрыв `claude` посреди ответа, нет сети, 4K и масштаб 150 %. Любой краш или зависание дольше 1 с = провал.

Отчёт — `docs/rust/perf/<дата>-<commit>.json` по схеме из `docs/rust/PERF.md` и дашборд-артефакт для владельца: все метрики, «до / после», тренд, проваленные тесты с причиной.
