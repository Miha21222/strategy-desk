# ТЗ: Strategy Desk на Rust

Nov 25, 2026 · @Michael

## Цель и решения

Strategy Desk 0.3 — нативное приложение на Rust с собственным UI, которое открывается меньше чем за секунду, весит в установщике до 30 МБ и показывает только цикл макро-ревью из MVP. Сейчас это Electron 0.2.3: установщик 181 МБ, распакованный 669 МБ, около 30 тыс. строк TypeScript.

Зачем переезжаем (ответы владельца 25.11):

- выучить Rust на живом проекте;
- лёгкий установщик для партнёра и бати;
- надёжность: без ловушек asar, путей к claude.exe и venv, на которых горели 0.2.1–0.2.3;
- быстрый запуск .exe и отзывчивый интерфейс.

Что решено:

| Вопрос | Решение |
| --- | --- |
| Интерфейс | Чистый Rust UI, без браузера и WebView |
| Движок чата | Только Claude (claude CLI). Codex убираем |
| Функции за `legacyUi` | Выбрасываем: «День», «Воркфлоу», Strategy Lab, аналитика, база курса gt-rag |
| Python-часть vault | Остаётся: `scale.py`, `macro_shots.py`, скилл `macro-review`. Desk их не считает, только показывает |
| Концепция | Заметка 23 без изменений: аугментация, «сначала человек», «Почему так» показывает все факторы |

Принцип переписывания: контракт файлов `state/` и поведение для трейдера сохраняются, а всё, что вокруг, делаем заново и проще.

## Почему сейчас медленно

Тормозит не столько Electron, сколько то, что приложение делает само: на старте заранее поднимает сессию claude.exe, а потом раз в минуту запускает Python для проверки tvmcp. Переписав на Rust и оставив эту логику, мы бы сохранили половину проблемы. Поэтому каждая причина ниже становится правилом новой версии.

| Что происходит сейчас | Где в коде | Что делаем в Rust |
| --- | --- | --- |
| Установщик 181 МБ, из них claude.exe от SDK — 226 МБ в распакованном виде. Defender сканирует всё это при первом запуске | `electron-builder.yml`, SDK 0.3.278 | Один `strategy-desk.exe` на 10–20 МБ. Claude Code ставится официальным установщиком из мастера, и только если его ещё нет |
| На старте сразу поднимается сессия claude.exe для будущего чата | `app.tsx` → `chat.prewarm`, `agent.ts: prewarmFor` | Никакого прогрева. Сессия стартует, когда человек начал печатать в чате |
| Каждые 20 с: `tasklist`, два HTTP-запроса к CDP и чтение `.credentials.json`; раз в 60 с — `tvmcp --check`, то есть полный запуск Python с numba (таймаут до 60 с) | `app.tsx: STATUS_POLL_MS = 20_000`, `status.ts: TVMCP_CACHE_MS` | Лампочки обновляются по событиям и по кнопке. Процесс TradingView смотрим через WinAPI (`sysinfo`), без запуска `tasklist`. `tvmcp --check` — только в мастере и в «Проверке» |
| Любое событие чата (каждый кусочек ответа) меняет состояние в корневом компоненте, и перерисовывается всё приложение с Markdown всех сообщений | `app.tsx: setMessages` (строки 285–330) | UI рисует кадр из готового состояния. Markdown сообщения разбирается один раз и кэшируется, заново разбирается только то сообщение, которое сейчас печатается |
| Снимки PNG читаются в base64 и передаются строкой через IPC | `macro-state.ts: readShot` | Декодируем PNG в фоновом потоке в текстуру один раз, превью уменьшенные |
| Любое изменение в `state/` перечитывает весь день: около 22 файлов, `macro_*.json` по 2000 строк, плюс `lessons.md` и CSV оценок | `macro-state.ts: loadDay` | Перечитываем только изменившийся файл (`notify` сообщает имя), в фоновом потоке, с разбором `serde` |

Целевые цифры для приёмки: холодный запуск до первого кадра — меньше 1 с; в простое занято меньше 1 % CPU и меньше 80 МБ RAM; после записи файла скиллом экран обновляется быстрее чем за 200 мс.

## Выбор UI-библиотеки

Рекомендация — **egui** (через `eframe`). В ней уже есть всё, что нужно Desk: своё рисование для спидометра, Markdown для чата, картинки для снимков. Первый экран на ней собирается за вечер, а для начинающего в Rust это важнее красоты дефолтных виджетов.

|  | egui | Slint | Iced |
| --- | --- | --- | --- |
| Как пишется UI | Обычный Rust-код, строится каждый кадр (immediate mode) | Свой язык разметки `.slint` + Rust для логики | Архитектура Elm: состояние → сообщения → view |
| Порог входа для новичка | Низкий | Средний: два языка сразу | Высокий: много типов и трейтов |
| Спидометр Fear & Greed | `Painter`: дуги, стрелка, зоны | `Path` в разметке | `Canvas` |
| Markdown в чате | Готовый крейт `egui_commonmark` | Готового нет, собирать самим | Встроенный виджет `markdown` |
| Внешний вид из коробки | Рабочий, «инструментальный»; своя тема обязательна | Самый аккуратный | Средний |
| Нагрузка в простое | Перерисовка только по событию или `request_repaint` | По изменению свойств | По сообщению |
| Лицензия | MIT / Apache-2.0 | GPLv3, бесплатная royalty-free для десктопа или коммерческая | MIT |

Риск egui — стиль «панель инструментов». Для нетехнического человека нужна своя тема: шрифт Inter с кириллицей, крупные отступы, скруглённые карточки, светлая и тёмная палитра из нынешнего `styles.css`. Это закладываем на этапе 1. Если после прототипа спидометра вид не понравится, смена на Slint стоит только слой `ui`: ядро от него не зависит.

## Архитектура новой версии

Один `strategy-desk.exe` из трёх крейтов. Интерфейс никогда не ждёт диск, сеть или другой процесс: он отправляет команды в фон и рисует последний снимок состояния. Именно это убирает подтормаживания.

&#91;embedded content: архитектура · 3 крейта в одном exe и 4 внешние части\]

Скилл пишет файлы в vault, `desk-app` замечает изменение и читает только этот файл, окно перерисовывается. Обратно в vault Desk пишет только два файла владельца. Планировщик запускает тот же exe без окна, поэтому ручной и запланированный обзор идут одним путём.

| Крейт | Главные зависимости | Что переезжает из TS |
| --- | --- | --- |
| `desk-core` | `serde`, `serde_json`, `chrono`, `chrono-tz`, `csv` | `shared/macro.ts`, `shared/preflight.ts`, `renderer/setup.ts`, `main/macro-env.ts`, `vault-template.ts` (чистая часть) |
| `desk-app` | `tokio`, `notify`, `keyring`, `sysinfo`, `reqwest`, `include_dir` | `main/macro-state.ts`, `agent.ts`, `drivers/claude.ts`, `tasks.ts`, `status.ts`, `tv-launch.ts`, `updater.ts`, `store.ts` |
| `desk-ui` | `eframe` / `egui`, `egui_commonmark`, `image`, `tray-icon` | `renderer/macro/*`, `chat/*`, `components/` (Sidebar, Settings, SetupWizard, PreflightList, Help, Toasts), `i18n/ru.ts` |

Настройки и чаты остаются в `%APPDATA%\strategy-desk` в тех же JSON-файлах, поэтому новая версия подхватит существующие. Секреты, зашифрованные Electron safeStorage, придётся ввести один раз заново: их формат привязан к Chromium.

## Синхрон со скиллом daily-trading-plan

Desk и скилл смотрят на день с двух сторон и на двух горизонтах. **Скилл — локальная история для заработка:** направление и цели хода от IB в пределах доступного движения (остаток ADR, проекции IB1 и IB2), плюс статистика. **Desk — полная картина:** стрелка с доводами, макро, мнение ИИ, ход всего дня и похожие дни для анализа на будущее. Обмен идёт через файлы vault.

Решено 25.11: план стоит рядом со стрелкой, а не внутри неё; цели плана показываются сверху, машинные — в «Подробнее». Скилл daily-trading-plan (версия 1.17) работает на ПК avitr и пишет на [Доску гипотез](https://claude.ai/artifact/7jKxzphbLp3jne2UU67UjE), а Desk и vault живут на ноутбуке. Поэтому обмен идёт через базу доски, а не через файлы vault. Акцент на ход от IB входит в скилл строкой «Окно от IB» поверх пути по сессии: путь остаётся, и разбор оценивает оба.

&#91;embedded content: день · два горизонта, файлы идут стрелками\]

Порядок дня подстроен под расписание скилла: он строит план в 8:45 и 15:15, раньше обзора Desk. Поэтому Desk делает ранний сбор в 08:30 и 15:00 (макро и похожие дни на доску), а стрелку считает как раньше, в 09:30 и 16:00, уже видя план. Разбор плана скилл делает на следующее утро. Если сбора Desk к 8:45 нет, план строится без него, как сейчас.

### Контракт файлов

Общее место — база Доски гипотез. Коллекции `hypotheses`, `chats`, `meta/lessons` уже ведёт скилл, новая `desk` — для Desk. Регион: `eu` — FDAX1! и FESX1!, `us` — ES1! и NQ1!. Отдельный `plan_stats.csv` не нужен: разборы доски и есть статистика планов.

| Документ доски | Пишет | Читает | Поля |
| --- | --- | --- | --- |
| `hypotheses/<D>_<SYM>` (есть) | Скилл: план в 8:45 / 15:15, разбор на следующий день | Desk | Как сейчас (`bias`, `summary`, `theses`, `plan`, `macro`, `review`) плюс новое `ib`: `side`, `reach` (IB1 или IB2), `window`, `in_adr`, `why`; в разборе — `review.ib`: сторона первого пробоя IB, IB1 и IB2 достигнуты ли в окне, совпала ли сторона |
| `meta/lessons` (есть) | Скилл после разбора | Desk | Активные уроки |
| `meta/stats` (новый) | Скилл в пятницу и по запросу | Desk | Корзины (важные новости в окне / нет, стрелка Desk за / против плана, режим, регион): число дней, доля совпадений направления и стороны IB, доля IB1 и IB2, медиана размаха план / факт, E по сделкам, где есть R; до 3 выводов словами |
| `desk/<D>_<eu\|us>` (новый) | Desk: сбор в 08:30 / 15:00, стрелка в 09:30 / 16:00, итог в 20:00 | Скилл | `asof`, `macro` (время, событие, важность), `similar` (до 5 дней: что совпало, ход дня, ход от IB), `regime`; после обзора — `side`, `needle`, `zone`, `top_long` и `top_short` (по 2 довода); в 20:00 — `review` (ход дня, попала ли стрелка, «Твой взгляд») |

**Как Desk достаёт до доски — проверить первым.** У приложения на Rust своего доступа к базе артефакта нет. Вариант 1: скилл `macro-review` в Claude Code на ноутбуке сам читает и пишет доску, если у него есть инструменты Artifact. Вариант 2 (запасной): запланированная задача Claude на ноутбуке служит мостом: копирует планы и разборы с доски в `state/board_<D>_<SYM>.json`, а файлы Desk — в `desk` на доске. В любом случае сам Desk читает только файлы vault.

«Отпечаток дня» для поиска похожих дней собирается из того, что известно до открытия: гэп и ночной диапазон в % ADR, контекст D1 (точка A, PO3), режим, сторона и сила стрелки, теги новостей и важные события в окне. Результат похожего дня считается двумя цифрами: ход дня и ход от IB.

Мерок две, по одной на горизонт. План и «Твой взгляд» оцениваются по ходу от IB: в какую сторону был первый пробой IB и дошла ли цена до IB1 / IB2. Стрелка оценивается по ходу всего дня.

Это меняет мерку стрелки: сейчас её оценивают по ходу окна за 2 ч. Оценка по окну остаётся в CSV ещё 20 торговых дней рядом с дневной, чтобы не потерять историю и сравнить обе мерки. Потом пересматриваем доли факторов: группа «окно» (45 %) подбиралась под окно, а не под день. Вывод по корзине делаем только при 10 днях и больше, иначе пишем «мало данных». Главная мера — матожидание, доли попаданий его только дополняют.

### Что меняется в Desk

- **«Твой взгляд».** Если план есть, вопрос звучит так: «План: от IB — шорт до IB1. Всё ещё так?». Нажать всё равно нужно: за час до окна мнение могло измениться.
- **Рядом со стрелкой** — плашка «План на окно: …» с первого тезиса доски. Стрелка говорит про день, план — про ход от IB, и подписи это называют. Когда стороны расходятся, под стрелкой появляется одна строка с самым сильным доводом против. В расчёт стрелки план не входит.
- **«Что делать».** Сверху таблица тезисов плана с доски (окно от IB, POI с ценами и окнами, отмена) и кнопка «Открыть план на доске». Машинные уровни и цели `scale.py` переезжают в «Подробнее» с пометкой «расходится с планом», где это так. Без плана блок выглядит как сейчас.
- **«Похожие дни» (новая карточка).** До 3 дней: что совпало и чем закончилось — день целиком и ход от IB. Если для того дня есть разбор на доске, показывается и его вердикт. Пусто, пока истории меньше 20 дней.
- **«Кто был прав»** — две строки: «Ход от IB: ты и план» (план — из `review.ib` доски, появляется на следующее утро) и «День: стрелка».
- **«Неделя в пять строк»** — первая строка выводов из `meta/stats`, например: «Окно от IB совпало 7 из 10, в дни важных новостей — 2 из 5».
- **Этапы.** Чтение файлов доски (через мост) — этап 3. Набор файлов, которые Desk пишет сам, не меняется: по-прежнему только два файла владельца; на доску пишет скилл `macro-review` или мост.

### Что меняется в скиллах

- **daily-trading-plan 1.18 (предложена карточкой в чате).** Новый раздел «Окно от IB»: IB — первые 30 минут сессии, окно — 2 ч от открытия. В плане оно идёт первой строкой текста и первым тезисом: сторона пробоя IB, цель IB1 или IB2, укладывается ли в остаток ADR. Путь по сессии остаётся как есть. Разбор добавляет строку «Окно от IB» и `review.ib` по барам M30. Перед планом скилл читает `desk/<D>_<region>`, если он есть: макро-список для сверки со своим и похожие дни. По пятницам пишет `meta/stats`. Счётчики уроков считают пару инструментов за одно наблюдение.
- **macro-review / `scale.py` (Python vault).** Новая команда `similar`; `review` добавляет `day_move` и оценивает стрелку по дню (плюс по окну в переходные 20 дней); ранний «сбор» в 08:30 / 15:00, чтобы план в 8:45 / 15:15 уже видел макро и похожие дни; восстановить задачу 20:00. Эти правки можно делать уже сейчас, до Rust-версии.
